# R1188 Banner Edit: 新規登録 -> English

## Status: ALREADY IMPLEMENTED (two methods)

The 新規登録 (New Registration) banner replacement was already completed.
No additional R1188 atlas pixel editing is needed.

## Method 1: EXE Glyph ID Patch (active in build)

File: `build/patch_exe.py` -- PATCH 4

The EXE menu struct records that define the banner's 4 kanji tiles were
patched to reference ASCII glyph slots instead of kanji glyph slots:

| Cell | Kanji | EXE Offset | Old Glyph IDs | New Glyph IDs | Display |
|------|-------|-----------|----------------|---------------|---------|
| 1    | 新    | 0x3C33F0  | 719, 720       | 46(N), 69(e)  | Ne      |
| 2    | 規    | 0x3C3428  | 721, 722       | 87(w), 0(spc) | w       |
| 3    | 登    | 0x3C3268  | 705, 706       | 50(R), 69(e)  | Re      |
| 4    | 録    | 0x3C32A0  | 707, 708       | 71(g), 14(.)  | g.      |

Result: banner reads **"New Reg."** using existing ASCII glyphs from the
R1272 font atlas. No R1188 pixel editing required.

## Method 2: PCSX2 Texture Replacement (backup/overlay)

File: `build/pcsx2_texture_replacements/a2d3fce36c8c719d-e786e0650b284c64-r120x24-00002214.png`

A 120x24 RGBA replacement texture renders "New Character" over the
original 新規登録 sprite at GS page 0x2214 with CLUT hash e786e0650b284c64.
This is generated by `tools/patch_r1188_tabs.py`.

## Why direct R1188 atlas editing is unnecessary

The banner is NOT composed from individual kanji cells baked into R1188.
Instead, the game's EXE contains menu struct records that reference
glyph IDs from the R1272 font atlas. The 120x24 composite is assembled
at runtime from these glyph references. By patching the glyph IDs in
the EXE (Method 1), the game renders English letters from the existing
ASCII portion of R1272 -- no texture atlas pixel manipulation needed.
