R2100 Palette / CLUT Analysis
=============================
Date: 2026-06-01

FORMAT CORRECTION
-----------------
Previous analysis (packdata_secondary_analysis.txt) incorrectly labeled the pixel
format as PSMT8H. The TEX0_1 register value 0x2000000621410000 decodes to:

  PSM = 0x14 = PSMT4 (4-bit indexed, 16 palette entries)
  TW  = 8 (256 pixels wide)
  TH  = 8 (256 pixels tall)
  TBW = 4 (buffer width = 256 pixels)
  CBP = 0 (CLUT base pointer)
  CSA = 0 (CLUT storage address offset)
  CLD = 1 (load CLUT on draw)

This is the SAME pixel format as R1272 (PSMT4), just with a smaller texture
(256x256 vs R1272's 256x512).


CLUT STRUCTURE
--------------
Each block stores a CLUT of 192 bytes = 48 RGBA entries = 3 sub-palettes of 16.
The 3 sub-palettes represent 3 text colors, each with 16 alpha gradient levels.
The game selects which sub-palette to use at runtime via the CSA (CLUT Storage
Address) field in TEX0.

  Sub-palette 0: Orange/Gold  RGB=(255, 143,  51)
  Sub-palette 1: Dark Brown   RGB=( 20,  13,   4)
  Sub-palette 2: Dark Crimson RGB=(105,   0,  17)

CLUT locations in PACKDATA.DIG:
  Block 0: Embedded in GS packet chain (no separate CLUT at file level)
  Block 1: File offset 0x10EC0
  Block 2: File offset 0x19600
  Block 3: File offset 0x21D40
  Block 4: File offset 0x2A480
  Block 5: Shares Block 4 CLUT or loaded at runtime

PIXEL VALUE MAPPING
-------------------
In ALL CLUTs across ALL blocks:

  Index  0: HIGHEST alpha (~122-125) = MOST OPAQUE  -> TEXT FOREGROUND
  Index 15: Alpha = 0               = TRANSPARENT   -> BACKGROUND

  Indices 1-14: Smoothly decreasing alpha = ANTIALIASED EDGES

This is IDENTICAL to R1272's convention:
  R1272 palette: index 0 = (172,172,172,128) most opaque, index 15 = (0,0,0,0) transparent
  generate_font_atlas.py: game_val = 15 - min(val * 15 // 255, 15)
    white pixel (255) -> index 0 (opaque text)
    black pixel (0)   -> index 15 (transparent bg)


CONCLUSION: RENDERING ENGLISH TEXT FOR R2100
--------------------------------------------
1. Use pixel value 0 for TEXT pixels (opaque foreground)
2. Use pixel value 15 for BACKGROUND pixels (transparent)
3. Use values 1-14 for antialiased edges (1=nearly opaque, 14=nearly transparent)

This is the SAME mapping as R1272. The generate_font_atlas.py conversion formula
works correctly for R2100 as well:

    game_val = 15 - min(val * 15 // 255, 15)

The 3 sub-palettes (orange, brown, crimson) provide different text colors, but
all use the same alpha gradient structure. English text rendered with the above
mapping will work correctly with ALL sub-palettes because the pixel values only
select the alpha level, and the base color is fixed per sub-palette.

The game selects which sub-palette (color) via the CSA field in TEX0 at runtime.
Our English pixel data does NOT need to care about which color is used -- it just
needs to use the correct alpha-level indices (0=opaque, 15=transparent).

PS2 GS alpha note: stored alpha values are 0-128 range (not 0-255). The PS2 GS
treats alpha=128 as fully opaque. The max alpha in R2100 CLUTs is ~124-125,
which is nearly fully opaque (97-98% opacity).
