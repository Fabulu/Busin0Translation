# KNOWN ISSUES - Busin 0 English Translation Patch

## Critical Issues

### 1. Black Screen on Name Entry (and possibly other UI screens)
- **Symptom**: Screen goes completely black after intro narration. Game still responds to input (sounds play, characters can be entered blindly).
- **Likely Cause**: Font atlas (R1272) has incorrect palette/alpha values. Glyphs may be rendering as transparent or black-on-black.
- **Root Cause Investigation**: The English font atlas (`build/english_font_atlas.bin`) was generated by `tools/generate_font_atlas.py`. The palette (CLUT) must match the original PS2 PSMT4 format with correct alpha channel. PS2 alpha is 0-128 (not 0-255), and the MSB may need to be set for visibility.
- **Status**: INVESTIGATING

### M13. EXE Font Width Patch Breaks Stats/Menus (REVERTED)
- **Symptom**: Stat labels (力, 知恵 etc.) and menu buttons disappeared after EXE font width patch.
- **Cause**: The width table covers ALL glyphs 0-247. Changing widths for positions 0-94 also affected Japanese glyphs at those same positions (some kanji use glyph IDs in the ASCII range).
- **Fix**: Reverted EXE to original. Font width patch needs to ONLY modify glyph positions that are exclusively used by English text, OR all Japanese labels need to be translated first.
- **Status**: REVERTED

### M14. Text Truncation Due to Display Box Size Limit
- **Symptom**: English dialogue gets cut off mid-sentence ("A heavy fog had settled over", "The city was deathly s")
- **Cause**: The game's text renderer has a fixed display area. Japanese text (12px wide kanji, ~18 per line, 2-3 lines) fits in fewer glyphs. English text at same glyph widths takes 1.5-2x more glyphs and overflows.
- **Root Cause**: NOT the Section 1 patcher (opcodes are correct). The renderer simply clips after a pixel/character limit.
- **Fix Options**: (A) Shorter/more concise translations, (B) Add FFD2 page breaks to split across pages, (C) EXE patch renderer to allow more lines/chars (hard)
- **Status**: NEEDS TRANSLATION REVISION

### M10. Space as Exclamation Mark / Wrong Punctuation (FIXED in v6)
- **Symptom**: Spaces rendered as !, apostrophes as em-dashes, periods as >, commas as =
- **Cause**: Glyph table used arbitrary glyph positions. Game uses ASCII formula: glyph_id = char_code - 0x20.
- **Fix**: Rebuilt glyph table using ASCII-0x20 formula for all 95 printable characters.

### M11. Lowercase at Wrong Position (FIXED in v7)  
- **Symptom**: Lowercase a-z showed as hiragana (positions 112-137)
- **Cause**: Assumed lowercase at 112+. Actual position follows ASCII: 'a'(0x61)-0x20 = glyph 65.
- **Fix**: a-z now at glyphs 65-90. Found by analyzing name entry save state RAM.

### M12. Variable-Size Injection NOT Safe (RE-CONFIRMED in v7/v8)
- **Symptom**: v7 variable-size caused fast-forwarding again despite correct PACKDATA rebuild.
- **Root Cause**: Section 1 opcode 0x0004 (DISPLAY_TEXT) uses GLYPH_OFFSET and GLYPH_COUNT — these are byte positions into Section 2, NOT message indices. When Section 2 grows, all offsets shift.
- **Opcode format**: `0004 0000 GLYPH_OFF 0000 GLYPH_COUNT` where byte_offset = GLYPH_OFF * 2
- **Evidence**: Recon found 36 text display opcodes in R1198, all using glyph offsets.
- **Fix Options**: (A) Fixed-size injection (current, causes truncation) or (B) Patch Section 1 GLYPH_OFFSET values to match new Section 2 layout after injection.
- **Status**: Using fixed-size (v8). Option B is the proper fix but requires Section 1 opcode patching.

### M7. Uppercase Letters Render as Hiragana (DIAGNOSED)
- **Symptom**: First letter of words like "HUMAN" shows as kana (う, お, き, え). Lowercase works.
- **Cause**: The EXE's ASCII mapping table at 0x3C08A2 maps ASCII sequentially: char_code - 0x20 = glyph_id. So both 'A' (0x41) and 'a' (0x61) map to glyph 33 (0x41-0x20=33, but also our a=33). Uppercase A-Z maps to glyphs 33-58 (same as our lowercase a-z). Our uppercase A-Z at glyphs 112-137 lands in the hiragana range, showing kana.
- **Fix**: Replace font atlas glyphs 33-58 with UPPERCASE letters. All text will render uppercase-only (game can't distinguish case). OR redesign glyph table to put uppercase at 33-58.
- **Status**: DIAGNOSED, NEEDS FIX

### M9. R1198 Section 2 Growth Causes Text Loop (WORKAROUND)
- **Symptom**: Early game text loops infinitely — same scenes replay, can't progress past intro.
- **Cause**: R1198 Section 2 grew from 5,874 to 11,718 bytes (English text 2x longer). The event script in Section 1 has hardcoded byte offsets into Section 2 for scene flow control. When Section 2 grows, these offsets point to wrong message positions, causing the script to loop.
- **Workaround**: Reverted R1198 to original Japanese. Early game intro/guild scenes stay Japanese.
- **Fix Needed**: Either (a) truncate/abbreviate English translations to fit original Section 2 size, or (b) patch Section 1's byte offsets to match new Section 2 layout, or (c) use fixed-size message slots with padding.
- **Status**: WORKAROUND APPLIED — R1198 reverted

### 2. Intro Narration Still in Japanese
- **Symptom**: Opening slideshow narration (R1193, R1194) displays Japanese text about the Battle of Banquo.
- **Cause**: R1193 and R1194 were not included in translated resources. They fall outside the R1196-R1213 range we targeted.
- **Fix**: Translate R1193/R1194 content, add to injection pipeline.
- **Status**: IDENTIFIED, NOT FIXED

### 3. Name Entry Frozen/Black (v3 rebuild)
- **Symptom**: Name entry screen either completely black (v3 sequential rebuild) or frozen with empty grid.
- **Cause**: v3 PACKDATA rebuild script started data at sector 17 (calculated TOC size). Original PACKDATA has 125 sectors of header/TOC data before first resource. The 108 extra sectors contain critical boot data. v3 overwrote them with resource data, shifting ALL resource sector positions.
- **Root Cause**: Our rebuild script calculated `toc_sectors = ceil(2883*12/2048) = 17` but the original uses 125 sectors for the header area. The v1 script correctly read `hdr = f.read(125 * SECTOR)` and started data at sector 125.
- **Fix**: Use 125-sector header like v1, update ISO directory record data length for the 6KB growth.
- **Lesson**: ALWAYS preserve the original file's header structure. Don't recalculate layout from first principles — copy the original header verbatim.
- **Status**: FIXED in rebuild_packdata_v5.py

## Resolved Issues (Mistakes Log)

### M1. VIF FIFO Crash on Boot (FIXED)
- **Symptom**: `Assertion failed in function ReadFIFO_VIF1: FQC = 0 on VIF FIFO READ!`
- **Cause**: 93 binary-data type-02 resources (UI layouts, coordinate tables, map tiles) were injected with the dialogue injector, corrupting their 3D scene data (Section 1).
- **Root Cause**: The type-2 injector processed ALL type-02 resources that had entries in the translation batches, including batch 10-11 entries that were binary data tagged as `[DATA]`/`[LAYOUT]`.
- **Fix**: Removed all 93 binary-data resources from `build/packdata_resources/`, restoring originals.
- **Lesson**: Only inject resources that have REAL translated dialogue, not binary data entries.

### M2. Type-03/06 Resource Corruption (FIXED)
- **Symptom**: Black screen or potential crashes from R46, R47 (type-03), R1053 (type-03), R1908 (type-06).
- **Cause**: The v2 MSG pipeline treated these non-MSG resources as flat glyph streams, corrupting their binary structure. Type-03 = 3D scene data, type-06 = mixed data.
- **Fix**: Removed R46, R47, R1053, R1908 from patched set. Lost ~50 translated strings (minor labels) but gained stability.
- **Lesson**: Only inject into resource types confirmed to use MSG format (type-01, type-02 with dialogue, type-15, type-20, type-44).

### M3. Luna Bar Crash in v1 (FIXED in v2)
- **Symptom**: Entering the Luna Bar tavern crashed the game.
- **Cause**: R43 message stream corruption — v1 pipeline split on FFFF only (29 groups) but translations indexed by FFFE-counted messages (88 messages). English text injected at wrong boundaries.
- **Fix**: v2 pipeline properly handles both FFFF and FFFE delimiters.
- **Lesson**: Must understand the exact binary format before injection.

### M4. Font Atlas Palette Position in v1 (FIXED)
- **Symptom**: All text appeared as garbage/wrong characters.
- **Cause**: `palette = orig[-64:]` read wrong bytes.
- **Fix**: Read palette from correct position.
- **Lesson**: Verify pixel data visually at known glyph positions before building ISO.

### M6. Font Atlas Palette ALL-WHITE (FIXED in v3)
- **Symptom**: Name entry grid empty, text potentially rendering with wrong colors/transparency.
- **Cause**: `palette = orig[192:256]` reads from offset 192 which is all-0xFF pixel data, NOT the palette. The real palette is at atlas offset 65728 (end of file) and contains a grayscale ramp (172→0) with PS2 alpha (0x80=opaque, color 15 has 0x00=transparent for background).
- **Fix**: Copy real palette from `orig[16+65728:16+65792]` into `eng_atlas[65728:65792]`.
- **Lesson**: Always verify palette by checking actual RGBA values. All-0xFF is obviously wrong for a 16-color grayscale palette.

### M8. R39 Extra FFFF Terminator → Tavern Softlock (WORKAROUND)
- **Symptom**: Tavern softlocks after Vera dialogue — music plays, no menu appears, can't select anything.
- **Cause**: Patched R39 (type-15, equipment/menu resource) has 657 FFFF terminators vs original's 656. Extra FFFF shifts all message indices, causing menu system to read wrong data.
- **Root Cause**: The v2 pipeline's injection of R39 introduces an extra message terminator somewhere. Needs investigation in `build_full_english_v2.py` offset table rebuild for type-15 resources.
- **Workaround**: Reverted R39 to original Japanese. Equipment menus show Japanese but game doesn't softlock.
- **Fix Needed**: Debug v2 pipeline's handling of type-15 (Format A with offset table) resources.
- **Status**: WORKAROUND APPLIED

### M5. R1370/R2100 Missing from Rebuilt PACKDATA (FIXED)
- **Symptom**: These resources had `skipped=True` in manifest but original PACKDATA had valid data.
- **Cause**: Rebuild script zeroed TOC entries for skipped resources instead of preserving originals.
- **Fix**: Only 2 resources affected, both type-04 (models). The game may or may not load them.
- **Lesson**: Verify TOC against original for any zeroed entries that shouldn't be.
